# Лабораторна робота №1b: Моделювання з використанням UML

**Тема:** Code repository (на прикладі GitHub)  

---

## 1. Опис предметної області
**GitHub** — це найбільша у світі веб-платформа для хостингу IT-проєктів та спільної розробки (колаборації), що базується на системі контролю версій Git. Платформа об'єднує в собі функції хмарного файлового сховища для вихідного коду, інструменти соціальної мережі для розробників, систему відстеження помилок (Issue Tracking) та потужний рушій автоматизації CI/CD (GitHub Actions).

Архітектурно система побудована на мікросервісному підході, де за авторизацію, роботу з файловою системою (Git RPC), пошуковим індексом та управлінням Pull Request-ами відповідають окремі ізольовані компоненти, об'єднані єдиним API шлюзом.

*(Детальний опис термінів предметної області наведено у файлі `Glossary.md`)*.

8. **Activity Diagram (Діаграма діяльностей)** *Алгоритм обробки команди `git push` на стороні сервера з розгалуженням на паралельні процеси.* ![Activity Diagram](UML_Models/Activity.png)

Це рішення зумовлене тим, що стандартного синтаксису UML 2.x цілком вистачило для повного та точного опису предметної області. Потреби створювати власні метакласи чи кастомні стереотипи (що є основним призначенням Profile Diagram) не виникло.

## 3. Проєктування нової функціональності ("Live Architecture Visualizer")

Під час аналізу платформи було виявлено, що розробникам (особливо при роботі з великими проєктами на C++ чи Java) часто важко оцінити, як зміна кількох класів у Pull Request впливає на загальну архітектуру системи. 

**Ідея покращення:** Впровадження вбудованого інструменту автоматичної генерації UML прямо в інтерфейсі GitHub. 
Інструмент "Live Architecture Visualizer" працюватиме як фоновий аналізатор. Коли розробник створює Pull Request, сервіс автоматично парсить змінені файли (наприклад, заголовки класів), витягує оновлені зв'язки (наслідування, агрегацію) і порівнює їх з поточною архітектурою в гілці `main`. 
Якщо відбулися архітектурні зміни, система генерує актуальну Class Diagram (використовуючи рушії на кшталт PlantUML) і автоматично публікує її як перший коментар до PR. Це робить Code Review значно наочнішим.
