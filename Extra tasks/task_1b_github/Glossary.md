# Глосарій предметної області "Системи керування репозиторіями коду" (на прикладі GitHub)

Даний глосарій містить технічні терміни, визначення та концепції, що були використані при розробці UML-діаграм для моделювання платформи GitHub в межах лабораторної роботи №1b.

---

## 1. Контроль версій та керування кодом (VCS Core)

* **Repository (Репозиторій)** — базовий об'єкт зберігання проєкту. Містить усі робочі файли, історію змін, гілки та метадані. Може бути *Public* (доступний усім) або *Private* (доступний лише власникам та колабораторам).
* **Commit (Коміт)** — зафіксований стан файлової системи в певний момент часу. Кожен коміт має унікальний ідентифікатор (SHA-hash), посилання на автора, час створення та опис змін (commit message).
* **Branch (Гілка)** — паралельна лінія розробки. Дозволяє працювати над новою функціональністю (Feature branch) або виправленням помилок (Bugfix branch) без ризику пошкодити основний код (`main`/`master`).
* **Head** — вказівник на останній коміт у поточній активній гілці.
* **Merge (Злиття)** — операція об'єднання змін з однієї гілки в іншу. Git аналізує історію комітів і намагається автоматично поєднати правки.
* **Merge Conflict (Конфлікт злиття)** — ситуація, коли в двох гілках було змінено один і той самий рядок коду. Вимагає ручного втручання розробника для вибору фінальної версії.
* **Clone (Клонування)** — процес створення повної локальної копії віддаленого репозиторію на комп'ютері розробника.
* **Fork (Форк)** — копія репозиторію іншого користувача, яка створюється у власному просторі імен. Використовується для внесення змін у чужі проєкти (Open Source).

---

## 2. Колаборація та соціальні функції

* **Pull Request (PR) / Merge Request** — запит на перевірку та злиття коду з однієї гілки в іншу. Центральний інструмент для Code Review.
* **Code Review (Рев'ю коду)** — процес аналізу запропонованих змін у PR іншими розробниками. Мета — пошук багів, дотримання стилю коду та обмін знаннями.
* **Issue (Завдання/Проблема)** — інструмент для відстеження помилок, пропозицій щодо нових функцій або планування завдань. Підтримує мітки (Labels), призначення відповідальних (Assignees) та прив'язку до етапів (Milestones).
* **Organization (Організація)** — спільний акаунт для груп розробників або компаній. Дозволяє централізовано керувати великою кількістю репозиторіїв та правами доступу через команди (Teams).
* **Contributor (Контриб'ютор)** — користувач, який не є власником репозиторію, але робить внесок у проєкт через Pull Requests.
* **Star (Зірка)** — аналог "лайку" для репозиторію, що дозволяє користувачам додавати цікаві проєкти в обране та впливає на популярність проєкту в пошуку.

---

## 3. Автоматизація та CI/CD (GitHub Actions)

* **GitHub Actions** — система автоматизації робочих процесів. Дозволяє автоматично збирати, тестувати та деплоїти код безпосередньо в хмарі GitHub.
* **Workflow (Робочий процес)** — конфігураційний файл у форматі YAML (`.github/workflows/*.yml`), що описує правила автоматизації (наприклад, "запускати тести при кожному push").
* **Event (Подія)** — специфічний тригер, який запускає Workflow (наприклад: `push`, `pull_request`, `issue_opened`, `schedule`).
* **Job (Завдання)** — набір послідовних кроків (Steps), що виконуються на одному обчислювальному вузлі (Runner).
* **Runner (Ранер)** — сервер (віртуальна машина), на якому фізично виконуються команди Workflow. Може бути хмарним (Hosted) або власним (Self-hosted).
* **Secret (Секрет)** — зашифрована змінна середовища (наприклад, пароль до БД або API-ключ), яка використовується в Actions, але прихована від розробників у логах.

---

## 4. Архітектурні та інфраструктурні терміни

* **API Gateway** — проміжний шар, який приймає запити від клієнтів (Web, CLI), перевіряє їх на безпеку та перенаправляє до відповідних внутрішніх мікросервісів.
* **Microservice (Мікросервіс)** — автономний програмний модуль, що відповідає за вузьку частину бізнес-логіки (наприклад, сервіс авторизації, сервіс репозиторіїв, сервіс пошуку).
* **Git RPC (Spokes)** — внутрішній протокол GitHub для швидкої передачі та обробки Git-об'єктів між серверами зберігання та API.
* **Webhook (Вебхук)** — механізм сповіщення сторонніх систем про події в GitHub за допомогою HTTP POST запитів.
* **Load Balancer (Балансувальник навантаження)** — пристрій або програма, що розподіляє вхідний мережевий трафік між декількома серверами для забезпечення стабільності та швидкодії.
* **Persistence Layer (Шар зберігання)** — комбінація баз даних (MySQL для метаданих, Redis для кешу) та файлових систем для зберігання великих масивів двійкових даних (Git objects).
