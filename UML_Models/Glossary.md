# Глосарій проєкту "Link Manager" (Менеджер посилань)

## 1. Предметна галузь (Domain Entities)

* **Посилання (Link / LinkData)** — базова інформаційна структура даних системи. Містить URL-адресу, видобутий заголовок (Title), користувацький опис, а також зв'язки з папкою та набором контекстів (тегів).
* **URL (Uniform Resource Locator)** — стандартизована адреса певного ресурсу (вебсторінки) в інтернеті, яка є унікальним ідентифікатором посилання в системі.
* **Папка (Folder)** — сутність для строгого ієрархічного групування. Кожне посилання може належати лише до однієї папки (відношення `1-до-багатьох` / `1:N`).
* **Контекст / Тег (Context)** — мітка для гнучкої багатовимірної категоризації. Одне посилання може мати багато контекстів, що дозволяє реалізовувати складні перетини при фільтрації (відношення `багато-до-багатьох` / `N:M`).
* **Метадані (Metadata)** — "дані про дані". У контексті проєкту це автоматично видобута інформація з вебсторінки (наприклад, HTML-тег `<title>`).

## 2. Архітектура та принципи проєктування (Architecture & Design)

* **Ядро системи (LinkManagerCore)** — виділена компонентна статична бібліотека (`.a` / `.lib`), що інкапсулює всю бізнес-логіку програми. Створена під час рефакторингу для ізоляції даних від графічного інтерфейсу.
* **MVC (Model-View-Controller)** — головний архітектурний патерн застосунку, який розділяє програму на три незалежні шари:
    * **Model (Менеджер посилань / LinkManager)** — інкапсулює колекцію посилань, логіку їх обробки (CRUD) та стан даних.
    * **View (Графічний інтерфейс / MainWindow)** — візуальна оболонка на базі Qt Widgets. Відповідає виключно за відображення даних та прийом команд від користувача (без складної логіки обробки).
    * **Controller (MainController)** — координатор, який приймає сигнали від View, оновлює Model і навпаки.
* **Low Coupling (Низька зв'язність)** — принцип проєктування, досягнутий у проєкті шляхом винесення логіки в `LinkManagerCore`, що дозволяє змінювати UI без впливу на логіку роботи з даними.
* **SOLID** — набір принципів ООП, застосованих у проєкті. Наприклад:
    * *Single Responsibility (SRP)* — клас `WebUtils` відповідає тільки за мережу, `DatabaseManager` — тільки за БД.
    * *Open/Closed (OCP)* — систему експорту відкрито для додавання нових форматів, але закрито для модифікації старих (завдяки інтерфейсам).
* **CRUD (Create, Read, Update, Delete)** — чотири базові функції управління даними (створення, читання, оновлення, видалення), реалізовані у класі `LinkManager`.

## 3. Патерни проєктування (Design Patterns)

* **Strategy (Стратегія)** — поведінковий патерн, реалізований через інтерфейси `IExportStrategy` та `IImportStrategy`. Дозволяє динамічно перемикати алгоритми (формати CSV, JSON, HTML) під час виконання програми.
* **Singleton (Одинак)** — твірний патерн, застосований до `DatabaseManager`. Гарантує, що у програмі існує рівно один екземпляр підключення до бази даних, надаючи глобальну точку доступу до нього.
* **Observer (Спостерігач) / Сигнали та Слоти (Signals & Slots)** — вбудований механізм фреймворку Qt для реактивного програмування. Дозволяє об'єктам (наприклад, `WebUtils`) сповіщати інші об'єкти про зміну стану (наприклад, отримання title сторінки) без жорсткої залежності між ними.

## 4. Зберігання, Мережа та Обробка даних (Data & Network)

* **Менеджер бази даних (DatabaseManager)** — клас-обгортка для взаємодії з дисковим сховищем.
* **SQLite** — легковажна реляційна система управління базами даних (СУБД), яка зберігає всі дані у звичайному локальному файлі, що ідеально підходить для десктопних застосунків.
* **Мережеві утиліти (WebUtils)** — модуль-клієнт на базі нативного класу `QNetworkAccessManager` для виконання HTTP/HTTPS запитів.
* **Асинхронність (Asynchrony)** — підхід до виконання операцій (наприклад, завантаження вебсторінок), при якому програма не блокує головний потік (UI-потік) в очікуванні відповіді від сервера.
* **QR-генератор (QRCodeGen)** — сторонній алгоритм, що конвертує текстовий URL у матричний двовимірний штрих-код (QR-код) для кросплатформної передачі посилання на мобільний пристрій.

## 5. Інструментарій та Тестування (Tools & Quality Assurance)

* **Модульне тестування (Unit Testing / QtTest)** — процес автоматизованої перевірки ізольованих частин коду (функцій, класів бібліотеки `LinkManagerCore`) на коректність роботи за різних умов (RoundTrip тести).
* **UML (Unified Modeling Language)** — стандартизована мова візуального моделювання, використана для побудови архітектурних креслень системи (Class, Sequence, Component діаграми тощо).
* **Doxygen** — система автоматичної генерації професійної документації безпосередньо з коментарів у вихідному коді (`.h` та `.cpp` файлах).
* **Graphviz** — утиліта для автоматичної побудови графів, яка використовується разом із Doxygen для візуалізації UML-діаграм залежностей і спадкування у згенерованій документації.
